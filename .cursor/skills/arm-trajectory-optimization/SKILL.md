# 机械臂轨迹优化

## 项目边界

- 先查 AGENTS.md、实际源码和构建入口。主包当前位于 `参考文件/ros2_ws/src/arm_control`；路径变化时搜索定位。
- 附件方案与实际实现分开核实，没有 Git 历史时不声称已确定改动来源。
- 保留 `FollowJointTrajectory → joint_trajectory_controller → ArmSystem → Bus → CAN`。连续轨迹优先在生成层扩展，避免控制器直接发送 CAN 绕开保护。
- ROS 接口使用 rad、rad/s、s，关节名称和顺序取自配置，不硬编码四轴或混用 C620、MIT、RV 协议。
- 审查请求保持只读；实施请求完成代码、必要测试和文档。用户授权的范围决定是否修改。

## 轨迹检查与实施

1. 追踪 `scripts/send_trajectory.py`、`scripts/trajectory_path.py`、配置、Action 提交和实际反馈检查。
2. 保留单目标三次贝塞尔兼容入口。多路点使用单次 Action；全路径验证通过后才提交。
3. 区分归一化参数和秒数，导数包含时间尺度。使用整数纳秒，时间严格递增，连接点只保留一次。
4. 明确连续性等级。五次贝塞尔多段可用共享连接速度和零连接加速度实现 C2；反向转折停下，不承诺 jerk 连续或碰撞规避。
5. 校验所有路点维度、关节映射、有限值、持续时间、位置和导数限制。优先使用控制多边形及导数凸包界；保守界超限应拒绝并解释，不偷偷缩放目标。
6. 核对控制器插值是否与提供的位置、速度、加速度一致。不能用全零导数冒充运动轨迹，也不能仅检查采样点便声称全曲线限位成立。
7. 起点来自新鲜反馈并检查静止条件。预规划多段不等于运动中抢占、动态拼接或多客户端仲裁，交付中明确区分。
8. 保留故障锁存、超速、看门狗、显式恢复、标定及使能门槛；不连接或使能真实电机来执行离线测试。

## 验证与交付

- 最小复现覆盖非 1 秒时长、不同段长、重复时间、C2 连接、反向转折、缺轴/乱序、NaN、限位与 Action 失败。
- 修改纯 Python 算法时运行 `test/test_path.py`、`test/test_trajectory.py`；恢复逻辑用 `test/test_recover.py`。从包目录运行 `python -B test/test_path.py` 等命令。
- 改动总线时重新编译相关 C++ 测试，不把旧二进制通过当作当前源码验证。
- 更新 CMake 安装与测试注册；目标 ROS 环境用 colcon 构建、插件加载和模拟 Action 联测核实。缺少环境时明确未验证。
- 中文交付：已改行为、相关文件、实际测试结果、兼容性与剩余限制。不把理论分析、模拟或源码检查写成实机通过。
